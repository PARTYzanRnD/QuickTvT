# Plan: Defend Faction Restriction (Updated Design)

## Overview
Restrict players from rejoining the defend faction immediately after playing it.

## Design: Client-Side Only w/ RPC-Sent Defend Flag
- Server persists flagged player UIDs in a server-only `map<string, bool>` + JSON file.
- On `SLOTSELECTION`, server sends each player their flag status via `Rpc(RPC_SetDefendFlagToPlayer, ...)` in `OnPlayerConnected`.
- Client-side check `IsDefendFactionRestrictedForLocal()` blocks slot clicks locally.
- No `[RplProp]` needed for the flag state.
- Dropped `FreeSlot` restriction entirely — now just the group leader debug.

## Implementation

### 1. `scripts/game/PS_GameModeQuickTvT.c`
**Changes already applied:**
- Added `PS_DefendFlagJsonData` class for JSON serialization.
- Replaced `[RplProp]` approach with server-only `map<string, bool> m_mDefendFlagPlayers`.
- Added `LoadDefendFlags()` and `SaveDefendFlags()` for JSON persistence (`$profile:QTvT_DefendFlags.json`).
- Added `FlagDefendFactionPlayers()` called in `OnGameStateChanged` (GAME state) to flag playersUIDs.
- Added `OnPlayerConnected(int playerId)` override to send flag status via delayed `SendDefendFlagToPlayer()`.
- Added `RPC_SetDefendFlagToPlayer` to broadcast flag status to the specific player.
- `IsDefendFactionRestrictedForLocal(FactionKey factionKeyPlayer)` — client-side check using local `PS_PlayableControllerComponent.m_bIsDefendFlagged` + `m_sFlaggedDefendFactionKey`. Restricted for first 120000ms of slots.

### 2. `scripts/game/lib/QTvT_M_PlayableControllerComponent.c`
**Changes already applied:**

- `SendQTvTTimerCommand()` / `RPC_SendQTvTTimerCommand()` remain for timer commands.

### 3. `scripts/game/lib/QTvT_M_CharacterSelector.c`
